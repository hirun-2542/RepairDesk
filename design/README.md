# RepairDesk — UX/UI Design

ออกแบบตาม spec ระบบ Service / Repair Management (มือถือ · คอมพิวเตอร์ · รถยนต์ · เครื่องปรับอากาศ)
Flow: **รับงาน → ตรวจสอบ → เสนอราคา → อนุมัติ → ซ่อม → ชำระเงิน** · โชว์ **Workflow · Role · Status · File Upload · Audit Log**

| ส่วน | ไฟล์ |
|---|---|
| เอกสารนี้ | User Flow · Sitemap · Wireframe · Screen States · Design System |
| High-fidelity prototype (React + mock data) | [`prototype/`](prototype/) |
| ภาพตัวอย่าง (28 ภาพ) | [`screenshots/`](screenshots/) |

## วิธีรัน prototype

```bash
cd design/prototype
npm install
npm run dev            # http://localhost:5174
npm run build          # type-check + production build
npm run shots          # ถ่าย screenshot ทุกหน้า (ต้องมี preview server ที่ :5174)
node scripts/smoke.mjs # ไล่ workflow ครบวงจรผ่าน UI จริง พร้อม assert ทุก guard
```

- แถบดำด้านล่าง (**Prototype dock**) สลับบทบาท Admin / หน้าร้าน / ช่าง 1 / ช่าง 2 ได้ทันที และมีลิงก์ไปทุกหน้า (ซ่อนด้วย `?nodock=1`)
- พารามิเตอร์ใน hash: `#/jobs/j5?as=tech1&dialog=quote` — `as` = บทบาท (`admin|front|tech1|tech2`), `dialog` = เปิด dialog (`quote|complete|cancel`)
- Mock data: 12 งาน ครบทุกสถานะ/ทุกประเภท, 1 งานที่ถูกปฏิเสธราคา v1 แล้วเสนอ v2, 1 งานยกเลิกพร้อมค่าตรวจเช็ค, audit log 73 รายการ; เวลาอ้างอิงคงที่ (10 ต.ค. 2569 10:30) ให้ภาพซ้ำได้
- State เปลี่ยนจริงในหน่วยความจำ (ใช้กฎ workflow เดียวกับ plan: `checkAction`, `visibleActions`, `uploadableStages`) — รีเฟรชหน้าแล้วกลับเป็นค่าเริ่มต้น

## 1. ผู้ใช้และบทบาท (Role)

| Actor | เข้าระบบ | ทำอะไรได้ | ไม่เห็น/ทำไม่ได้ |
|---|---|---|---|
| **ผู้ดูแลระบบ** (ADMIN) | email + password | ทุกอย่างของ role อื่น, จัดการผู้ใช้, Audit Log | — |
| **หน้าร้าน** (FRONT_DESK) | email + password | รับงาน, มอบหมายช่าง, แนบรูปรับเครื่อง/สลิป, บันทึกอนุมัติ/ปฏิเสธแทนลูกค้า, เสนอราคาใหม่, ยกเลิก, รับชำระ, พิมพ์เอกสาร | เริ่มตรวจ/ซ่อม (งานช่าง), หน้า Admin |
| **ช่าง** (TECHNICIAN) | email + password | เฉพาะงานที่ได้รับมอบหมาย: เริ่มตรวจ, ทำใบเสนอราคา, เริ่มซ่อม, แนบรูปผลตรวจ/ก่อน/หลังซ่อม, ซ่อมเสร็จ | งานของช่างคนอื่น (แสดงเป็น “ไม่พบ”), รับงานใหม่, หน้า Admin |
| **ลูกค้า** (ไม่มีบัญชี) | ลิงก์ส่วนตัว `/track/<token 32 ตัว>` | ดูสถานะ/ใบเสนอราคา/รูป/การชำระเงิน, อนุมัติหรือปฏิเสธใบเสนอราคา | ชื่อพนักงาน, Audit, โน้ตภายใน, สลิปโอน |


| หน้า | Admin | หน้าร้าน | ช่าง | ลูกค้า |
|---|:-:|:-:|:-:|:-:|
| `/login` | ✓ | ✓ | ✓ | – |
| `/jobs` กระดานงาน | ทุกงาน | ทุกงาน | เฉพาะงานตน | – |
| `/jobs/list` | ทุกงาน | ทุกงาน | เฉพาะงานตน | – |
| `/jobs/new` | ✓ | ✓ | “ไม่พบ” | – |
| `/jobs/:id` | ✓ | ✓ | เฉพาะงานตน (อื่น = “ไม่พบ”) | – |
| `/jobs/:id/receipt` | ✓ | ✓ | เฉพาะงานตน | – |
| `/admin/users`, `/admin/audit` | ✓ | “ไม่พบ” | “ไม่พบ” | – |
| `/track/:token` | – | – | – | ✓ (ไม่ต้อง login) |

การนำทางหลัก: **เมนูด้านซ้าย (sidebar)** จัดเป็นกลุ่ม “งานซ่อม” (กระดานงาน · รายการงาน · รับงานใหม่) และ “ผู้ดูแลระบบ” (ผู้ใช้ · Audit Log — เฉพาะ ADMIN) แสดงเฉพาะรายการที่ role นั้นใช้ได้ · ด้านล่างสุดเป็นชื่อผู้ใช้ + role + ปุ่มออกจากระบบ · รายการปัจจุบันมีแถบฟ้าและ `aria-current="page"` · ≥ 1100px กว้าง 248px; 720–1099px เหลือแถบไอคอน 68px (มี `aria-label`/`title`); < 720px กลายเป็นแถบไอคอนด้านบน

## 6. Design System

**แนวทาง:** *Accessible & Professional* — แอปภายในที่ใช้ทั้งวัน ต้องอ่านง่าย สแกนสถานะเร็ว ไม่ตกแต่งเกินจำเป็น (ผลจาก `ui-ux-pro-max --design-system` ใช้เฉพาะ palette navy + blue CTA; ส่วน pattern แบบ landing page และฟอนต์ serif ที่ได้มาไม่เหมาะกับแอปนี้จึงไม่ใช้)

### 6.1 สี (ค่า contrast คำนวณจริง, WCAG AA ต้อง ≥ 4.5:1)

| Token | ค่า | ใช้กับ | Contrast |
|---|---|---|---|
| `--navy-900` | `#0F172A` | sidebar, ตัวอักษรหลัก | 17.9:1 บนขาว (ป้ายกลุ่มเมนู `#94A3B8` 7.0:1, ลิงก์เมนู `#CBD5E1` 12.0:1 บนพื้นนี้) |
| `--accent` | `#0369A1` | ปุ่มหลัก, ลิงก์, focus | 5.9:1 (ขาวบน accent) |
| `--accent-hover` | `#075985` | hover ปุ่มหลัก | 7.6:1 |
| `--fg-muted` | `#475569` | ข้อความรอง | 7.6:1 บนขาว |
| `--danger` | `#B91C1C` | ผิดพลาด/ปุ่มทำลาย | 6.5:1 |
| `--bg` / `--surface` / `--border` | `#F8FAFC` / `#FFFFFF` / `#E2E8F0` | พื้น/การ์ด/เส้น | – |

### 6.3 ระยะ · รัศมี · เงา · Motion

- Spacing 4px scale: 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 (`--s1…--s12`)
- Radius: 6 (tag) · 8 (ปุ่ม/ช่องกรอก) · 12 (การ์ด) · full (badge)
- Shadow 3 ระดับ: การ์ด · hover/popover · dialog
- Motion 150ms (hover) / 220ms (dialog, toast) · ใช้ opacity/transform เท่านั้น · เคารพ `prefers-reduced-motion`

### 6.4 Components

| Component | กฎสำคัญ |
|---|---|
| **Button** | Primary / Secondary / Ghost / Danger-outline / Danger · สูง ≥ 40px (ปุ่มหลักบนมือถือและปุ่มลูกค้า 44px) · 1 Primary ต่อบริบท · ปุ่มไอคอนล้วนมี `aria-label` |
| **Status badge** | ไอคอน + ข้อความ + พื้นอ่อน · ขนาดใหญ่ในหัวหน้างาน |
| **Stepper** | 7 ขั้นหลัก · ขั้นที่ผ่านแล้ว = ติ๊ก · ปัจจุบัน = วงแหวน · `aria-current="step"` · ยกเลิก = แบนเนอร์แดงแทน |
| **Job card** | เลขที่งาน · ไอคอนประเภท · ยี่ห้อ/รุ่น · ลูกค้า · ช่าง (ไม่มอบหมาย = สีส้มเข้ม) · เวลา |
| **Field** | label ตลอด (ไม่ใช้ placeholder แทน label) · `*` = จำเป็น · error ใต้ช่อง + ไอคอน + `aria-invalid` · help text |
| **Table** | เลื่อนแนวนอนในกรอบบนจอแคบ · แถวคลิกได้ + ลิงก์จริงในช่องแรก · `caption` สำหรับ screen reader |
| **Dialog** | focus เข้าช่องแรก · Esc/คลิกนอกปิด · คืน focus เดิม · ปุ่มยืนยันขวาล่าง |
| **Banner** | info / ok / warn / error · ไอคอน + หัวข้อ · `role="alert"` เฉพาะ error |
| **Toast** | มุมขวาล่าง · หาย 4.5 วินาที · ปิดเองได้ · `role="status"` |
| **Dropzone** | ลาก/เลือกไฟล์ · แสดงข้อจำกัด · progress · error ใต้โซน |
| **Audit timeline** | จุด + เส้น · ผู้ทำ · เวลา · “ดูรายละเอียด” เปิด JSON ก่อน/หลัง · ป้าย “แทนลูกค้า” |

### 6.5 Responsive

| Breakpoint | พฤติกรรม |
|---|---|
| ≥ 1480 | sidebar 248px + เนื้อหาจัดกลางสูงสุด 1480px · Board ใช้เต็มพื้นที่ (ภาพ 02b ที่ 1920px เห็นครบ 8 คอลัมน์) |
| 1100–1479 | sidebar 248px คงอยู่ · Sidebar ขวาของหน้างานคงอยู่ · Board เลื่อนแนวนอน |
| 720–1099 | sidebar เหลือแถบไอคอน 68px (ภาพ 02c) · หน้างานเรียงคอลัมน์เดียว · ตัวกรอง 2 คอลัมน์ |
| < 720 | sidebar กลายเป็นแถบไอคอนด้านบน (ภาพ 02d) · ฟอร์ม/ตัวกรอง 1 คอลัมน์ · ตารางเลื่อนในกรอบ · หน้าลูกค้าออกแบบ mobile-first (390) |

### 6.6 Accessibility

- Contrast ≥ 4.5:1 ทุกคู่ (ตรวจด้วยสคริปต์ ไม่ใช่ประมาณ) · focus ring 3px ทุกองค์ประกอบโต้ตอบ
- สถานะไม่สื่อด้วยสีอย่างเดียว · ข้อผิดพลาดมีไอคอน + ข้อความ
- ปุ่ม/ช่องกรอกที่โต้ตอบ ≥ 40px (หน้าลูกค้า 44px) · ระยะห่างระหว่างปุ่ม ≥ 8px
- ตารางมี `caption` (sr-only) · ช่องกรอกทุกช่องมี label · dialog มี `role="dialog" aria-modal`
- Toast/Banner แจ้งผลโดยไม่ย้าย focus (`role="status"`/`alert`)

## 9. ผลการตรวจ prototype

- `npx tsc --noEmit` (strict + `noUnusedLocals`) และ `npm run build` ผ่าน
- `node scripts/smoke.mjs` ผ่าน 10/10 รอบติดต่อกันหลังเปลี่ยนเป็นเมนูซ้าย (ก่อนหน้านี้รอบแรกสุดที่เคยล้มเกิดจาก race ของ script เอง ไม่ใช่บั๊กในแอป): front desk รับงาน → ช่างอื่นเปิดงานไม่ได้ → ช่าง A ตรวจ/ส่งใบเสนอราคา (validation + VAT 7%: 1,500 → ฿1,605.00) → ลูกค้าอนุมัติผ่าน token 32 ตัว → ซ่อม (ปุ่ม “ซ่อมเสร็จ” ถูกล็อกจนมีรูป AFTER; ไฟล์ `.txt` ถูกปฏิเสธและไม่ปลดล็อก) → หน้าร้านรับชำระ (โอนไม่มีสลิป = ปิดปุ่ม; เงินสดสำเร็จ) → Admin เห็น audit `job.create … job.complete` รวมผู้กระทำ “ลูกค้า (ลิงก์ติดตามงาน)”
- `scripts/shots.mjs` ตรวจ `scrollWidth ≤ innerWidth` ทุกภาพ (28 ภาพ ที่ 390 / 1024 / 1440 / 1920) — ไม่พบ overflow แนวนอน; ภาพ full-page ขยาย viewport เท่าความสูงหน้าเพื่อให้ sidebar สูงเต็มเหมือนตอน sticky จริง
- ตรวจภาพจริงทุกหน้า พบและแก้ (รวมรอบก่อนหน้า): Kanban ถูกตัดคอลัมน์, หน้ามือถือ overflow แนวนอน (702px บน viewport 390px), ตารางใบเสนอราคาล้นจอฝั่งลูกค้า, โหนด “ความคืบหน้า” ของหน้าลูกค้าลอยทับ sticky bar, เวลา audit ไม่ตรงกับเวลาตัดสินใจใบเสนอราคา
- ข้อจำกัดที่ยังไม่ได้ทดสอบ: ไม่ได้ทดสอบบน Safari/Firefox/อุปกรณ์จริง, ไม่ได้รัน screen reader, `window.print()` ยังไม่ได้ตรวจผลพิมพ์จริง (มี `@media print` ซ่อนเมนู/ปุ่ม), การลาก-วางไฟล์ทดสอบเฉพาะเลือกไฟล์ผ่าน input
